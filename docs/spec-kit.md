# Spec Kit initialization

`hybrid-sdlc init` installs this toolkit's canonical Spec Kit constitution and
templates into an existing top-level Git repository. It checks the locally
installed `specify` executable with `specify version --features --json`; the
command does not download or install Spec Kit.

```console
hybrid-sdlc init
hybrid-sdlc init --target-dir C:\work\my-project
hybrid-sdlc init --target-dir C:\work\my-project --dry-run
hybrid-sdlc init --target-dir C:\work\my-project --force --json
```

Without `--target-dir`, the current directory must be the top-level directory
of an existing Git repository. A nested directory, a missing directory, or a
directory outside Git is rejected. Missing canonical files are created.
Untracked or customized files are preserved and reported as `preserved` unless
`--force` is supplied. Force saves the exact replaced bytes below
`.specify/backups/` before replacing a file; each backup path is included in
the output. Review backups before removing them.

`--dry-run` performs the repository, Spec Kit, manifest, path, and ownership
checks and displays the same per-file plan without creating a directory,
manifest, journal, or backup. `--json` emits a JSON object with the repository,
per-path action, optional backup path, manifest location, and Spec Kit probe
result. Initialization errors are emitted as JSON when that mode is selected.

Initialization uses an atomic journal at
`.hybrid-sdlc-init-journal.json` before writing templates, backups, or the
ownership manifest. If a process stops partway through, rerun the same command.
The initializer compares exact current bytes with the recorded pre-state and
desired state. It finishes files that remain unchanged, recognizes files it
already wrote, and preserves edits made after interruption. A forced backup
uses the path and content recorded in the journal, so retrying cannot replace
the only saved copy with a later state. A malformed journal or ownership
manifest fails closed and remains available for inspection; do not delete it
until the repository contents have been reviewed.

The temporary journal includes template bytes and, during a forced replacement,
the original user bytes needed to recreate a backup after interruption. It is
removed after recovery completes and is ignored by Git while present. Treat it
as sensitive while an interrupted initialization is pending.

If a file existed before an interrupted operation and is deleted afterward,
recovery treats the deletion as a user change and leaves it absent for that
invocation. When the journal says the initializer was creating a file that was
already absent, a later absence is indistinguishable from an untouched
pre-state; rerunning initialization will create that file. The journal is
removed after a successful reconciliation, so this ambiguity applies only to
an interrupted first-time creation.

The ownership manifest `.specify/.hybrid-sdlc-manifest.json` tracks the exact
bytes generated by this toolkit. Customized and previously untracked files
remain user-owned unless force replaces them. Re-running initialization is
safe and does not alter templates that already match the packaged version.
